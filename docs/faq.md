# FAQ

Short answers, with the limits stated. Measurements cited here come with their raw files in `bench/`.

## What problem does HCS solve?

Context files for models (`AGENTS.md`, `CLAUDE.md`, summaries) drift from the code and nobody notices. HCS makes
every statement cite the code it comes from with a hash, so a plain `hcs check` (no model) says which statements
may no longer be true. It also measures how much a model recovers from the file, instead of assuming it.

## Does a valid `.hcs` file mean every claim is true?

No. It means each claim's quote was found in the cited source when it was compiled, and that the cited source has
not changed since it was sealed. Three things are not covered:

- **A faithful quote, an unfaithful paraphrase.** The quote check proves the words exist, not that the claim's
  wording says the same thing.
- **A wrong source.** If the code or a document is wrong, a claim that quotes it is wrong too
  (`examples/shop/README.md` shows this with an `AGENTS.md` that states a false refund window).
- **Changes outside the anchors.** A change elsewhere that makes a claim false goes unnoticed. Anchor claims to the
  code that enforces them; `seal --deps` also flags (as `review`) claims whose cited symbol uses code that changed,
  but on this repository 17 of 18 such flags were not needed (`bench/REPORT.md`, C3).

## How reliable is the fidelity score?

It is a measurement on a small sample, with a 95% confidence interval that HCS always prints. With 12 probes the
interval can span 50 points. The score depends on the answering model, the judge, and the probes, which are
generated by the compiling model and can share its blind spots. Use a judge from another model family, run
`--baseline` to see what the model knew without context, and `--filter-known` at compile time to set aside probes
models answer from general knowledge. A certificate records which models and settings produced it.

## Is the context always smaller than the code?

No. On a project of a few files the context can be larger than the source (about 1,800 tokens for 1,300 in
`examples/shop`): it organizes rather than compresses. On a mid-size project it was 7% of the source
(`bench/REPORT.md`, A1). Use `render --budget N` to fit a context window: the most important claims are kept.

## Which models work?

Any model behind an OpenAI-compatible API (OpenAI, Gemini, Groq, OpenRouter, Mistral, vLLM, LM Studio, Ollama),
and Anthropic. The full pipeline has been run on free tiers of Gemini and Groq, and on local models with Ollama
(`bench/REPORT.md`). Small local models (7B on CPU) produced weak results: they over-abstain. List the ids your key
can use with `hcs models <provider>`; do not guess them.

## The free quota ran out in the middle of a run. Did I lose everything?

No. `compile` saves the partial file and lists the missing chunks in an `@incomplete` header; `score` and `curve`
save every answered probe. Rerun the same command later (`compile ... --update`) and it resumes. Gemini's free tier
allows about 20 requests per day per model, and some model names share a quota; Groq's is counted in tokens per
minute and per day.

## Does my code leave my machine?

`check`, `seal`, `render`, `stats`, `impact`, `audit` (without `--probes`) and the MCP server never call a model or
the network. `compile`, `score`, `curve`, `compare`, `snapshot` and `audit --probes` send source text or the
context to the provider you choose. Some free tiers may use prompts for training: only send code you are allowed
to share, or use a local model.

## Is it safe to compile untrusted files?

Partly. Text addressed to a model ("ignore previous instructions") is detected by patterns, tagged `suspect`, kept
out of renders, and fails `check --strict`. On held-out attacks the patterns caught 7 of 15: treat it as a filter,
not a guarantee. Anchors cannot read outside the project root. Details in [SECURITY.md](../SECURITY.md).

## How precise are token counts?

By default they are estimates without a tokenizer. On this repository's context the estimate was 11% above the
count of one Groq model (`bench/c5/tokens-groq.txt`). `--tokenizer provider:model` asks the provider for real
counts (it may cost requests), and certificates then record it. Budgets always use the estimate, so that digests do
not depend on a provider.

## How does it find `path::Symbol`?

A built-in heuristic for brace languages, Python, Markdown, YAML and JSON. It reports what it cannot find as
missing and never guesses, but unusual syntax can give a wrong range. For TypeScript, JavaScript and Python,
`--parser tree-sitter` uses a real parser (optional packages); on this repository both agreed on 470 of 474
symbols, and every difference was a heuristic error (`bench/REPORT.md`, C5). The Python implementation has only
the heuristic.

## Is there a Python version?

`python/` implements the deterministic part (validate, check, seal, render, signatures) and passes the same
conformance suite as the TypeScript CLI. LLM commands are only in the TypeScript CLI. Neither is published on a
package registry yet: install from a clone.

## Is the format stable?

The format is: SPEC 1.0 (2026-10-22) freezes anchor syntax, hashing, verification statuses and digests across 1.x,
and readers accept every older version (0.1 to 0.3), so files keep working. Format changes go through an RFC
([rfcs/](../rfcs/README.md)). The CLI itself is still 0.3.0 and experimental.

## How does this compare to AGENTS.md, llms.txt, RAG or a summary?

HCS can sit next to them: it adds citations, staleness detection and a measured score to a context. `hcs audit`
checks an existing `AGENTS.md`. A longer comparison, and what HCS does not do, is in
[PRIOR_ART.md](../PRIOR_ART.md).
